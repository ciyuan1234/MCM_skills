# 时间预算与锁定模式

## 概述

数学建模竞赛的核心约束是**时间**。72 小时（CUMCM）或 96 小时（MCM）是硬性限制，
截止时间不会推迟。时间预算系统确保在任何时刻都清楚"还剩多少时间"和"应该做什么"。

## 时间预算分配（CUMCM 72h）

| 阶段 | 分配 | 小时 | 理由 |
|---|---|---|---|
| Phase 0 读题选题 | 7% | 5h | 三题对比 + 数据侦察 + 选题确认 |
| Phase 1 数据探索 | 8% | 6h | 数据质量决定建模上限 |
| Phase 2 建模求解 | 42% | 30h | 主体工作，含每个问题的建模+验证+灵敏度 |
| Phase 3 论文写作 | 28% | 20h | 含摘要迭代 + 排版 + 图表 |
| Phase 4 检查提交 | 12% | 9h | 含 checks/verify/Fresh-eyes + 打包 + 上传 |
| 缓冲 | 3% | 2h | 意外情况（环境问题、数据异常等） |

## 时间预算分配（MCM 96h）

| 阶段 | 分配 | 小时 | 理由 |
|---|---|---|---|
| Phase 0 读题选题 | 6% | 6h | 英文题目理解 + 文献调研 |
| Phase 1 数据探索 | 6% | 6h | 同上 |
| Phase 2 建模求解 | 40% | 38h | 同上，多 8h |
| Phase 3 论文写作 | 30% | 29h | 英文写作耗时更长 |
| Phase 4 检查提交 | 12% | 12h | 同上，多 3h |
| 缓冲 | 6% | 5h | 英文排版可能更耗时 |

## 时间检测机制

### 何时更新时间

1. **阶段切换时**：更新 `budget.elapsed_hours` 和 `budget.remaining_hours`
2. **长时间运行时**：每 6 小时输出一次时间状态
3. **会话恢复时**：重新计算 `remaining_hours = total_hours - elapsed_hours`

### 计算公式

```
elapsed_hours = sum(stage_durations_h.values())
remaining_hours = total_hours - elapsed_hours
effective_elapsed = elapsed_hours - (pause_offset_seconds / 3600)
effective_remaining = total_hours - effective_elapsed
```

**注意**：暂停时间（PAUSE 文件存在期间）从 elapsed 中扣除。

## 锁定模式

### 触发条件

当 `remaining_hours <= 6h` 时，**自动进入锁定模式**。

### 锁定模式规则

1. **拒绝新增建模/实验任务** — 不启动新的模型编写、数据处理、代码调试
2. **所有剩余时间投入写作、编译、打包** — 只做：论文完善、PDF编译、ZIP打包
3. **每 30 分钟输出状态行** — 格式：`[LOCKDOWN] 剩余 X.Xh | 已完成章节: ... | 阻塞项: ...`
4. **`remaining_hours <= 2h`**：只做 PDF 导出和 ZIP 打包，不做任何内容修改

### 锁定模式下的优先级

| 优先级 | 任务 | 说明 |
|---|---|---|
| P0 | PDF 导出 | 确保论文有可提交的 PDF |
| P1 | ZIP 打包 | 支撑材料打包 |
| P2 | 摘要数值检查 | 摘要关键数字与正文一致 |
| P3 | 格式检查 | 页数/字号/页边距合规 |
| P4 | 内容润色 | 如果时间允许 |

## 降级策略

当时间不足时，按以下梯度降级：

| 剩余时间 | 策略 |
|---|---|
| > 24h | 正常流程，所有阶段按计划执行 |
| 12-24h | 跳过灵敏度分析的高级部分（如多参数联合扰动）；简化图表（减少子图数量） |
| 6-12h | 只做基线模型，跳过高级优化（如模拟退火、遗传算法）；论文只写核心章节（问题重述/分析/模型建立/结果/评价） |
| < 6h | **锁定模式**：摘要 + 问题重述 + 模型框架 + 结果表 + PDF 导出 |

## 进度汇报

每 6 小时（或每次阶段切换时），输出进度汇报：

```
=== 进度汇报 ===
已用: X.Xh / 72h (XX%)
剩余: X.Xh
当前阶段: Phase N - [阶段名]
状态: [正常/落后/锁定]
关键结果: [摘要]
风险: [列表]
下一步: [具体行动]
================
```

## 滞后检测

如果当前阶段实际耗时 > 预算的 120%：
1. 输出警告：`[PACE] Phase N 已耗时 X.Xh，预算 Y.Yh，超出 20%`
2. 建议降级方案
3. 如果用户确认，执行降级

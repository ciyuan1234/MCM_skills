# Fresh-eyes 审查流程

## 概述

Fresh-eyes 审查是 Phase 4 的核心环节。模拟"刚拿到这篇论文的评委"视角，
清空建模过程中的上下文记忆，只看论文本身，找出逻辑漏洞和表述矛盾。

**不是多 Agent**，而是在同一 Agent 内做**角色切换**：
从"作者"切换为"评审"，利用上下文清空消除"作者盲区"。

## 执行时机

在 checks.py 和 verify.py 都通过后、PDF 导出前执行。

## 执行流程

### 第一轮 Fresh-eyes（15-20 分钟）

1. **清空上下文** — 显式声明："现在我忘掉所有建模过程，只看论文"
2. **只读论文** — 从头到尾读 paper.md，不看代码、数据、中间结果
3. **按清单逐项审查** — 使用下方审查清单
4. **记录问题** — 每个问题记录到 `decision_log.backcheck_logs`
5. **输出审查报告** — 格式见下方

### 修复

- 逐个修复发现的问题
- 每个修复都更新 paper.md

### 第二轮 Fresh-eyes（可选，10 分钟）

- 如果第一轮发现 ≥3 个问题，执行第二轮
- 只检查第一轮发现的问题是否已修复
- 最多 2 轮

## 审查清单

### 维度 1：逻辑连贯性

| 检查项 | 方法 | 判定 |
|---|---|---|
| 摘要结论有支撑 | 摘要声称的每个结论，正文是否有对应章节支撑 | 无支撑 → critical |
| 章节递进关系 | 每章结论是否由前文推导得出（不是凭空出现） | 断裂 → critical |
| 假设不被违反 | 正文是否隐式违反了声明的假设 | 违反 → critical |
| 方法与问题匹配 | 使用的方法是否真正回答了问题（不是"为了用而用"） | 不匹配 → warning |

### 维度 2：数值可信度

| 检查项 | 方法 | 判定 |
|---|---|---|
| 量级合理 | 关键数字的量级是否符合常识 | 异常 → critical |
| 单位正确 | 百分比、金额、重量等单位是否正确 | 错误 → critical |
| 数值范围 | 百分比是否在 0-100%，金额是否为正等 | 越界 → critical |
| "恰好完美" | 是否有恰好为整数、恰好为 0 等可疑数字 | 可疑 → warning |
| 数值一致 | 同一数值在不同位置出现时是否一致 | 不一致 → critical |

### 维度 3：表述一致性

| 检查项 | 方法 | 判定 |
|---|---|---|
| 模型描述一致 | 同一模型在不同章节的描述是否一致 | 矛盾 → critical |
| 术语一致 | 同一概念是否使用相同术语 | 混用 → warning |
| 缩写首次展开 | 所有缩写首次出现时是否展开 | 未展开 → warning |
| 符号与正文一致 | 符号说明表中的符号，正文是否按定义使用 | 不一致 → warning |

### 维度 4：图表对应

| 检查项 | 方法 | 判定 |
|---|---|---|
| 每图有引用 | 每张图在正文是否被引用 | 孤图 → warning |
| 每表有解读 | 每个表在正文是否有数据解读 | 无解读 → warning |
| 图表数据一致 | 图中数据是否与正文声称一致 | 不一致 → critical |
| 图表编号连续 | 编号是否有跳号 | 跳号 → warning |

### 维度 5：评委视角

| 检查项 | 方法 | 判定 |
|---|---|---|
| 可理解性 | 如果我是评委，我能理解这个解法吗 | 不理解 → critical |
| 创新点清晰 | 论文是否明确说明了创新/特异性 | 不清晰 → warning |
| 不足诚实 | 是否诚实讨论了模型局限性 | 未讨论 → warning |
| 结论有依据 | 结论是否由前文分析支撑 | 无依据 → critical |

## 审查报告格式

```markdown
## Fresh-eyes 审查报告

**时间**：[ISO8601]
**轮次**：第 1 轮
**审查视角**：评委（首次阅读）

### 发现的问题

| # | 维度 | 严重度 | 位置 | 问题描述 | 修复建议 |
|---|---|---|---|---|---|
| 1 | 逻辑连贯性 | critical | §5.2 | 弹性系数符号与§4.2符号说明不一致 | 统一为负号表示 |
| 2 | 数值可信度 | warning | 表12 | 损耗率恰好为5%（所有品类相同） | 说明是假设值还是计算值 |

### 审查结论

- critical 问题：X 个
- warning 问题：X 个
- 总体评价：[可提交/需修复后提交/需大幅修改]
```

## 写入 decision_log

审查结果写入 `decision_log.backcheck_logs`：

```json
{
  "check_id": "fresh_eyes_1",
  "timestamp": "...",
  "trigger": "Phase 4",
  "round": 1,
  "critical_count": 1,
  "warning_count": 1,
  "verdict": "patch_needed",
  "issues": [
    {"id": 1, "dimension": "逻辑连贯性", "severity": "critical", "location": "§5.2", "description": "..."}
  ]
}
```

## 与 L2 的关系

| 机制 | 执行时机 | 检查范围 | 方式 |
|---|---|---|---|
| L2-A/B/C | 阶段转换点 | 跨阶段一致性 | 结构化检查项 |
| Fresh-eyes | Phase 4 内 | 论文内容质量 | 角色切换 + 人工审查清单 |

两者互补：L2 检查"阶段之间是否一致"，Fresh-eyes 检查"论文本身是否可信"。

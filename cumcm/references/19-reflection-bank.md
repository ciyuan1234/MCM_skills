# 反思银行（Reflection Bank）

## 概述

反思银行是常见错误 + 修复方案的知识库。灵感来自 RBB-LLM (Nature 2025) 的
双循环反思机制和 Reflexion 框架的错误记忆机制。

**作用：**
- 阶段 2 每完成一个问题后，检查是否有匹配的反思条目
- Fresh-eyes 审查时，对照检查是否犯了已知错误
- 每次比赛结束后，将新发现的错误追加到反思银行

## 使用方式

### 在 Phase 2 中使用

完成一个问题的建模后，检查：
```
当前模型/方法 是否匹配反思银行中的"错误模式"？
├─ 匹配 → 读取"修复方案"，主动检查并修复
└─ 不匹配 → 继续
```

### 在 Fresh-eyes 审查中使用

清空上下文重读论文时，逐条对照检查：
```
论文中是否存在以下问题？
□ 对类别型变量做均值填充
□ 线性回归拟合非线性关系
□ 摘要最后没写
□ 敏感度只做了 ±10%
□ 假设没有编号引用
□ ...
```

### 在比赛结束后追加

将本次比赛遇到的新错误追加到 `reflections.json`：
```json
{
  "id": "RB-NEW-001",
  "category": "...",
  "error": "...",
  "symptom": "...",
  "fix": "...",
  "source": "2024C 实战",
  "added_at": "2024-09-05"
}
```

## 反思条目

### 数据处理类

| ID | 错误 | 症状 | 修复方案 |
|---|---|---|---|
| RB-D01 | 对类别型变量做均值填充 | 品类编码被平均后失去含义 | 类别型用众数填充或单独标记"未知" |
| RB-D02 | 不处理异常值直接建模 | 模型被极端值拉偏 | 先用 IQR 或 Z-score 识别，再决定剔除/截断 |
| RB-D03 | 忽略数据时间顺序 | 时序数据被随机打乱 | 时序数据必须按时间排序，不能 shuffle |
| RB-D04 | 多表合并时丢失误匹配 | 行数不对但没发现 | 合并后检查行数 = 原表行数 × 匹配率 |
| RB-D05 | 对时间序列做简单均值填充 | 趋势/季节性被平滑 | 用前后值插值或季节分解后填充 |
| RB-D06 | 百分比字段当数值处理 | 0-100 和 0-1 混用 | 统一为 0-1 或 0-100，检查数据字典 |

### 模型选择类

| ID | 错误 | 症状 | 修复方案 |
|---|---|---|---|
| RB-M01 | 对非线性关系用线性回归 | R² 很低，残差有明显模式 | 先画散点图，非线性时用多项式/对数/指数 |
| RB-M02 | 不做特征选择直接用全部变量 | 过拟合，解释性差 | 先做相关分析，保留 top-K 特征 |
| RB-M03 | 时序数据用普通回归 | 忽略自相关，DW 值异常 | 用 ARIMA/状态空间模型 |
| RB-M04 | 优化模型不检查可行性 | 结果违反约束 | 先验证约束满足，再报告目标值 |
| RB-M05 | 聚类前不标准化 | 大量纲变量主导距离 | 先 StandardScaler 再聚类 |
| RB-M06 | 不做基线模型直接用复杂模型 | 无法证明复杂度的必要性 | 先做简单基线，再升级，对比提升 |

### 论文写作类

| ID | 错误 | 症状 | 修复方案 |
|---|---|---|---|
| RB-W01 | 摘要先于正文写 | 摘要数值与正文不一致 | 正文完成后最后写摘要 |
| RB-W02 | 假设没有编号和引用 | 正文中无法引用假设 | 给每个假设编号 A1/A2/...，正文中引用 |
| RB-W03 | 敏感度只做 ±10% | 评委认为在糊弄 | 用龙卷风图排名+边界行为+结论翻转 |
| RB-W04 | 图没有结论解读 | 评委看不懂图的意义 | 每张图后写"由图X可看出..." |
| RB-W05 | 弱点写"可用更多数据" | 空话，无信息量 | 说出哪个参数、哪个数据源、不确定性多大 |
| RB-W06 | 参考文献凑数 | 12 条只引用 4 条 | 只列真读过的，5-10 条，每条在正文引用 |
| RB-W07 | 方程只陈述不推导 | 评委质疑正确性 | 每个方程展示推导过程 |
| RB-W08 | 代码与正文不一致 | 正文说遗传算法，代码是爬山法 | 代码必须与正文描述完全一致 |

### 代码实现类

| ID | 错误 | 症状 | 修复方案 |
|---|---|---|---|
| RB-C01 | 硬编码数据值 | 数据更新后代码失效 | 用 pd.read_csv 读取，禁止手写数据 |
| RB-C02 | 忘记设置随机种子 | 每次运行结果不同 | 脚本开头设 np.random.seed(42) |
| RB-C03 | 绘图没声明数据来源 | verify.py 报警告 | 文件头写 # 数据来源: <路径> |
| RB-C04 | 中文路径/编码问题 | UnicodeDecodeError | 用 UTF-8 编码，路径加引号 |
| RB-C05 | 不处理除零/NaN | 运行时报错 | 加 epsilon 或检查分母 |
| RB-C06 | MATLAB GBK 代码直接用 | 中文注释乱码 | 重写为 UTF-8 干净版 |

### 时间管理类

| ID | 错误 | 症状 | 修复方案 |
|---|---|---|---|
| RB-T01 | Phase 2 超时没开始写 | 最后赶工论文质量差 | Phase 2 最迟第 41h 必须开始写作 |
| RB-T02 | 灵敏度分析花太多时间 | 其他部分被压缩 | 灵敏度控制在 3h 内，用 OAT 做初筛 |
| RB-T03 | 不做时间检查 | 发现时只剩 6h | 每 6h 输出进度汇报 |
| RB-T04 | 试图做太多问题 | 4 个问题都做了但都浅 | 优先保证前 2 个问题深度，后 2 个可简化 |

## 条目格式（JSON Schema）

```json
{
  "id": "RB-XX-N",
  "category": "数据处理|模型选择|论文写作|代码实现|时间管理",
  "error": "错误描述",
  "symptom": "症状/表现",
  "fix": "修复方案",
  "source": "来源（比赛年份/文献/经验）",
  "added_at": "ISO8601 日期"
}
```

## 维护规则

1. 比赛结束后**必须**追加本次遇到的新错误
2. 追加时填写完整字段，不要只写 error
3. 每年赛前**复习**反思银行，确保已知错误不再犯
4. 如果某个修复方案失效，更新 fix 字段而不是删除条目
